# 1️⃣ PRD — 제품 요구사항 문서

## 1.1 제품 개요

| 항목             | 내용                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------ |
| **제품명**       | 완도 전복 다이어리 (가칭: AbaloneLog)                                                      |
| **한 줄 설명**   | 완도 전복 양식 어민이 현장에서 바로 먹이 기록을 남기고, AI가 적정 급이량을 분석해주는 웹앱 |
| **핵심 사용자**  | 전복 양식장을 직접 운영하는 어민 1인                                                       |
| **사용 환경**    | 스마트폰(현장) + PC/태블릿(사무실) — 반응형 웹앱                                           |
| **1차 MVP 범위** | 메인 대시보드(해양 환경 정보) + 먹이(사료) 기록 + 급이량 적정성 분석                       |
| **앱 구조**      | 메인 대시보드를 진입점으로, 탭 메뉴에서 각 기능 모듈로 이동하는 깊이 있는 구조             |

## 1.2 해결하는 문제

> **현재 상황:** 경험과 감으로만 운영 → 데이터 없음 → 과급이/부족급이 판단 불가, 비용 낭비 가능성

| 문제                                      | 프로그램이 제공하는 해결                                          |
| ----------------------------------------- | ----------------------------------------------------------------- |
| 앱 실행 시 무엇부터 해야 할지 모름        | 메인 대시보드에서 오늘 할 일(미기록 구역)과 해양 환경을 즉시 파악 |
| 바다 상황(파고·수온)을 별도로 확인해야 함 | 메인 화면에서 실시간 해양 환경 데이터를 한눈에 확인               |
| 위험 기상 시 미리 파악하기 어려움         | 파고·풍속 임계값 초과 시 경고 배너 자동 표시                      |
| 언제 얼마나 먹였는지 기억에 의존          | 구역별 급이 기록을 시간/날짜와 함께 저장                          |
| 적정 급이량을 모름                        | 기록 데이터 기반 분석 → 과급이/부족 경고                          |
| 6개 이상 구역을 따로 관리 불가            | 구역(가두리/수조)별 독립 기록 관리                                |
| 현장에서 기록이 불편                      | 모바일 최적화, 3탭 이내 입력 완료                                 |

## 1.3 핵심 기능 (MVP)

### 🥇 Must Have (1차 출시 필수)

**[메인 대시보드]**

0. **앱 전체 네비게이션 구조** — 상단 탭 메뉴(메인/구역관리/급이분석/해양정보/출하기록/설정) + 모바일 하단 내비게이션 바. 추후 메뉴 추가가 가능한 확장형 구조
1. **해양 환경 요약 카드** — 수온·파고·풍속·날씨 4종을 한 화면에 표시. 공공 API 실시간 데이터 연동
2. **기상 위험 알림 배너** — 파고 1.5m 이상 또는 풍속 10m/s 이상 시 상단 경고 배너 자동 표시
3. **5일 날씨 예보 슬라이드** — 기상청 단기예보 API 기반, 날씨 아이콘·기온·파고 요약
4. **수온 7일 추이 그래프** — 국립수산과학원 API 기반 스파크라인 차트
5. **구역별 오늘 급이 현황 요약** — 완료/미기록/일부 상태를 색상으로 구분하여 한눈에 파악
6. **빠른 작업 버튼** — 급이 기록하기(메인 CTA), 분석 보기, 구역 관리 등 주요 기능 바로가기

**[구역 관리 / 급이 기록]**

7. **구역 관리** — 양식장 구역(가두리/수조) 등록, 이름 지정, 6개 이상 지원
8. **급이 기록 입력** — 구역 선택 → 사료 종류 → 투입량(kg) → 저장 (3단계 이내)
9. **급이 이력 조회** — 구역별 / 날짜별 기록 목록 + 일별 합계
10. **적정 급이량 분석** — 최근 7일/30일 평균 대비 오늘 급이량 비교, 과급이·부족 시각적 표시
11. **알림/경고** — 당일 급이 미기록 시 저녁 푸시 알림 (선택 설정)

### 🥈 Should Have (1차 출시 후 우선 추가)

6. **성장 기록** — 전복 크기/상태 메모
7. **수온·수질 기록** — 환경 데이터 입력
8. **출하·판매 기록**
9. **폐사율 기록**

### 🥉 Nice to Have (장기 로드맵)

10. 기상청 API 연동 (수온 자동 입력)
11. 연간 생산량 통계 리포트
12. 다중 사용자(직원) 접근

# 2️⃣ TRD — 기술 요구사항 문서

## 2.1 기술 스택 권장안

| 레이어           | 선택                                        | 이유                                   |
| ---------------- | ------------------------------------------- | -------------------------------------- |
| **프론트엔드**   | React (Vite) + Tailwind CSS                 | 빠른 개발, 모바일 반응형               |
| **백엔드**       | Supabase (BaaS)                             | 서버 코드 최소화, 실시간 DB, 인증 내장 |
| **데이터베이스** | PostgreSQL (Supabase 내장)                  | 관계형 데이터, 무료 플랜 시작 가능     |
| **인증**         | Supabase Auth (이메일/전화번호)             | 어민 1인 사용, 간단 로그인             |
| **배포**         | Vercel (프론트) + Supabase (백엔드)         | 무료 티어로 MVP 운영 가능              |
| **알림**         | Web Push API + Service Worker               | 모바일 브라우저 푸시 알림              |
| **공공 API**     | 공공데이터포털 (data.go.kr) — 아래 2.4 참고 | 수온·파고·날씨 실시간 연동             |

## 2.2 비기능 요구사항

| 항목              | 요구사항                                                                   |
| ----------------- | -------------------------------------------------------------------------- |
| **반응형**        | 모바일(320px) ~ 데스크톱(1440px) 전 구간 지원                              |
| **오프라인**      | 인터넷 불안정한 바다 현장 → 기록 임시 저장 후 연결 시 동기화               |
| **속도**          | 급이 기록 저장 1초 이내, 메인 대시보드 초기 로딩 2초 이내                  |
| **보안**          | 사용자별 데이터 격리 (Row Level Security)                                  |
| **백업**          | 일 1회 자동 백업 (Supabase 내장)                                           |
| **API 장애 대응** | 공공 API 응답 실패 시 "데이터 일시 unavailable" 안내 후 마지막 캐시값 표시 |

## 2.3 내부 API 엔드포인트 (Supabase 자동 생성)

```
GET    /zones              — 구역 목록 조회
POST   /zones              — 구역 등록
GET    /feeding_logs       — 급이 기록 조회 (필터: zone_id, date)
POST   /feeding_logs       — 급이 기록 저장
GET    /feeding_analysis   — 적정 급이량 분석 결과
```

## 2.4 외부 공공 API 연동 명세 ⭐ (메인 대시보드용)

| API 명             | 제공 기관          | 데이터 포털 URL             | 제공 데이터              | 갱신 주기  |
| ------------------ | ------------------ | --------------------------- | ------------------------ | ---------- |
| **실시간수온정보** | 국립수산과학원     | data.go.kr/data/15130641    | 수온·염분·파고·풍속·풍향 | 실시간     |
| **해양기상 정보**  | 국립해양측위정보원 | data.go.kr/data/15033708    | 풍향·풍속·수온·기압·파고 | 실시간     |
| **단기예보 조회**  | 기상청             | data.go.kr/dataset/15000099 | 날씨·기온·강수확률       | 3시간 간격 |

### API 활용 절차

1. 공공데이터포털(data.go.kr) 회원가입
2. 각 API 활용 신청 → 개발 계정 발급 (즉시~1일 소요)
3. API 키(serviceKey)를 환경변수에 저장 (`VITE_WATER_TEMP_API_KEY` 등)
4. 완도 관측소 코드: 국립수산과학원 기준 **완도(WD)** 또는 인근 해양관측지점 사용

### 호출 예시 (수온 API)

```
GET https://apis.data.go.kr/1192000/ObsWaterInfo/getObsWaterList
  ?serviceKey={API_KEY}
  &obsCode=WD
  &dataType=JSON
```

# 3️⃣ User Flow — 사용자 흐름도

## 3.0 앱 전체 구조 (Navigation Architecture)

```
[로그인/회원가입]
    │
    ▼
┌─────────────────────────────────────────────┐
│              메인 대시보드 (홈)               │  ← 진입점
│  해양환경 · 날씨예보 · 구역현황 · 빠른작업     │
└───────┬───────┬────────┬────────┬───────────┘
        │       │        │        │
        ▼       ▼        ▼        ▼
   [구역관리] [급이분석] [해양정보] [출하기록]  ← 탭 메뉴

                              [설정] (프로필·알림·API 키)
```

**설계 원칙:** 메인 대시보드는 모든 기능의 진입점. 각 기능은 독립 모듈로 탭에서 접근. 추후 탭 메뉴에 새 항목을 추가하는 방식으로 기능 확장.

## 3.1 메인 대시보드 플로우

```
[앱 실행]
    │
    ▼
[메인 대시보드]
 ┌──────────────────────────────────┐
 │ ⚠️ [기상 경고 배너] — 조건부 표시   │  파고 1.5m↑ 또는 풍속 10m/s↑ 시
 ├──────────────────────────────────┤
 │ 🌊 해양 환경 카드                  │  공공 API 실시간
 │    수온 18.4°C · 파고 0.6m        │
 │    풍속 3.2m/s · 날씨 맑음         │
 ├──────────────────────────────────┤
 │ 📈 수온 7일 추이 그래프             │  국립수산과학원 API
 ├──────────────────────────────────┤
 │ 📅 5일 날씨 예보 슬라이드           │  기상청 단기예보 API
 ├──────────────────────────────────┤
 │ ⚡ 빠른 작업 버튼                   │
 │   [급이 기록하기] ← 메인 CTA        │
 │   [급이 분석] [구역 관리] [해양 상세]│
 ├──────────────────────────────────┤
 │ 🗂️ 구역별 오늘 현황                 │
 │   가두리A ✅  가두리B ✅            │
 │   가두리C ⚠️  가두리D ❌           │
 └──────────────────────────────────┘
    │
    ├─ [급이 기록하기] 탭 → 3.2 급이 기록 플로우
    ├─ [구역 관리] 탭   → 구역 관리 페이지
    ├─ [급이 분석] 탭   → 3.3 분석 조회 플로우
    └─ [해양 정보] 탭   → 해양 상세 페이지
```

## 3.2 메인 플로우: 급이 기록 입력

```
[앱 실행]
    │
    ▼
[홈 대시보드]
 ← 오늘 급이 현황 요약
 ← 미기록 구역 빨간 표시
    │
    ▼ [+ 급이 기록] 버튼 탭
    │
    ▼
[STEP 1] 구역 선택
 ┌─────────────────────────┐
 │  가두리 A  가두리 B  가두리 C  │
 │  가두리 D  수조 1   수조 2   │
 └─────────────────────────┘
    │ 구역 선택
    ▼
[STEP 2] 사료 정보 입력
 ┌─────────────────────────┐
 │ 사료 종류: [미역 ▼]       │
 │ 투입량:   [  25  ] kg    │
 │ 메모(선택): [____________]│
 └─────────────────────────┘
    │ [저장] 버튼
    ▼
[저장 완료 + 분석 결과 표시]
 ┌─────────────────────────┐
 │ ✅ 가두리 A 기록 완료      │
 │ 📊 오늘: 25kg            │
 │    7일 평균: 22kg         │
 │    → 적정 범위 ✅          │
 └─────────────────────────┘
    │
    ▼
[홈으로 돌아가기 or 다음 구역 기록]
```

## 3.3 초기 설정 플로우 (최초 1회)

```

    │
    ▼
[급이량 추이 그래프]
```

# 4️⃣ Database Design — 데이터베이스 설계

## 4.1 테이블 구조

### `users` — 사용자

| 컬럼명     | 타입      | 설명                |
| ---------- | --------- | ------------------- |
| id         | UUID (PK) | 사용자 고유 ID      |
| phone      | VARCHAR   | 전화번호 (로그인용) |
| name       | VARCHAR   | 어민 이름           |
| farm_name  | VARCHAR   | 양식장 이름         |
| created_at | TIMESTAMP | 가입일              |

---

### `zones` — 양식장 구역

| 컬럼명        | 타입              | 설명                          |
| ------------- | ----------------- | ----------------------------- |
| id            | UUID (PK)         | 구역 고유 ID                  |
| user_id       | UUID (FK → users) | 소유 어민                     |
| name          | VARCHAR           | 구역 이름 (예: 가두리 A)      |
| type          | ENUM              | 'cage'(가두리) / 'tank'(수조) |
| abalone_count | INTEGER           | 전복 수량(마리)               |
| is_active     | BOOLEAN           | 활성 여부                     |
| created_at    | TIMESTAMP         | 등록일                        |

---

### `feeding_logs` — 급이 기록 ⭐ (핵심 테이블)

| 컬럼명     | 타입              | 설명                                  |
| ---------- | ----------------- | ------------------------------------- |
| id         | UUID (PK)         | 기록 고유 ID                          |
| zone_id    | UUID (FK → zones) | 어느 구역                             |
| user_id    | UUID (FK → users) | 기록한 어민                           |
| feed_type  | VARCHAR           | 사료 종류 (미역, 다시마, 배합사료 등) |
| amount_kg  | DECIMAL(8,2)      | 투입량 (kg)                           |
| fed_at     | TIMESTAMP         | 급이 일시                             |
| memo       | TEXT              | 메모 (선택)                           |
| created_at | TIMESTAMP         | 기록 생성일                           |

---

### `feed_analysis` — 분석 기준값 (시스템 관리)

| 컬럼명               | 타입              | 설명                          |
| -------------------- | ----------------- | ----------------------------- |
| id                   | UUID (PK)         | -                             |
| zone_id              | UUID (FK → zones) | 해당 구역                     |
| recommended_daily_kg | DECIMAL(8,2)      | 권장 일일 급이량              |
| over_threshold_pct   | INTEGER           | 과급이 경고 기준 (%) 기본 120 |
| under_threshold_pct  | INTEGER           | 부족 경고 기준 (%) 기본 80    |
| updated_at           | TIMESTAMP         | 기준값 업데이트일             |

## 4.2 핵심 쿼리 예시

```sql
-- 오늘 구역별 급이 총량 조회
SELECT z.name, SUM(fl.amount_kg) as today_total
FROM feeding_logs fl
JOIN zones z ON fl.zone_id = z.id
WHERE fl.user_id = :user_id
  AND DATE(fl.fed_at) = CURRENT_DATE
GROUP BY z.name;

-- 7일 평균 급이량 (구역별)
SELECT zone_id, AVG(daily_total) as avg_7days
FROM (
  SELECT zone_id, DATE(fed_at) as day, SUM(amount_kg) as daily_total
  FROM feeding_logs
  WHERE fed_at >= NOW() - INTERVAL '7 days'
  GROUP BY zone_id, DATE(fed_at)
) daily
GROUP BY zone_id;
```
